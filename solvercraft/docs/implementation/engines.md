## Certificates and result semantics

QP and conic optimality requires a revalidated original-domain candidate and an independently restored finite Lagrangian bound/gap. Small stationarity residual alone is insufficient. Residual corrections use either a certified positive lower eigenvalue or the original variable box. Missing bounds on free coordinates can therefore leave a converged backend at Stationary/BestFound. Large additive objective constants are removed from gap arithmetic and restored outward for reported bounds.

Original objective, dot products, rows and quadratic triples now use the shared exact dyadic accumulator, rounded only once. QP certificates form their Lagrangian and gradient from original-unit rows/multipliers, independently of normalized solver rows. Conic and LP basis certificates also accumulate product/triple residuals before rounding; directed enclosures preserve nonzero subnormal residuals. Safety margins still use absolute product sums rather than only cancelled final values. A negative calculated gap is not clamped to zero to obtain Optimal. If certificate-only arithmetic fails, the verified primal point is retained with no fabricated bound. Original-unit dual/warm-state overflow is explicit. Meaningful final working-objective rounding or a nonrepresentable duplicate coefficient aggregate causes `numeric_range`, rather than silently changing a model or concealing comparison precision.

Conic duals are projected into the actual dual cones before calculating bounds. An approximate backend infeasibility ray is accepted only when it independently separates the original variable box: the minimum of `(A' z)'x` over that box exceeds `b'z` by an arithmetic margin. An unchecked ray stays Unknown. In particular, this implementation does not infer original MILP unboundedness from an unbounded continuous relaxation.

Supported conic unboundedness requires an independently validated feasible anchor and recession direction: exact-sign zero quadratic/equality recession, valid inequality/cone recession and strictly negative normalized linear descent. A finite blocker prevents this result regardless of magnitude, including a positive product that underflows when multiplied before the proof check. Missing a simple feasible anchor or exact-zero conditions gives Unknown rather than an unproved ray.

Each indicator direction uses `a'x-z<=rhs`, `0<=z<=M` and either `z+Mb<=M` (active1) or `z-Mb<=0` (active0). This preserves the original small RHS separately. An independent review demonstrated that directly forming `rhs+M` could exclude original feasible x=3,b=1 when M≈1e20; the slack-gate regression now passes. Two equality directions receive separate auxiliaries.

Mixed search retains bounds for open and closed branches, never discards an unresolved fixed-integer leaf as infeasible, and retains a verified incumbent on node/iteration/evaluation/cancellation interruption. Finite integer domains must fit the exactly distinguishable f64 adjacent-integer range. It has no cutting-plane, conflict-learning, parallel-tree or advanced MIP warm-start claim.

The final integer-rounding probe confirmed a real premature-node-closure defect: binary `x,y`, objective `1e12*x+500*y`, and row `1e9*x+y<=1` produced a near-integral LP point and incorrectly certified its rounded zero incumbent. The executed pre-fix CLI returned Optimal/0; the two initial regression tests failed. The corrected LP search retains the rounded incumbent but checks its constant-free objective against the relaxation bound before closing the node, using exact-sign comparison. A material gap triggers branching on any actual nonzero integer fraction even within the integer-distance tolerance. The mixed-conic path likewise keeps unmatched fixed-domain leaves unresolved rather than closing from a backend status alone. The same actual CLI then returned Optimal/500 at `[0,1]`, with bound500 and gap0; a one-node limit retains incumbent0 with an open valid bound and BestFound status.

## Cancellation, memory and portability

The primary conic API owns `Arc<dyn RunControl>` because Clarabel's callback requires `'static`. No lifetime casts or unsafe code are used. Native borrowed compatibility uses a scoped worker with cancellation and progress forwarding. WASM borrowed compatibility explicitly requires the owned API, which has synchronous callbacks. Backend setup/factorization is not preemptible mid-factor; input validation, conservative fill estimates and callbacks bound supported runs rather than promising hard realtime preemption. No native BLAS/LAPACK/Pardiso feature is enabled.

Owned algebraic adapters validate the original input budget before copying it. Direct mixed-conic admission additionally shares the complete affine-cone shape/nonzero/fill preflight with the continuous backend, before allocating integer search state or cloning relaxation models. Binary implicit bounds are included. Cancellation encountered during this preflight becomes a typed Cancelled/Unknown result with zero relaxation solves, allowing the facade's owned deadline control to retain TimeLimit versus explicit cancellation. The two controls in `tests/admission.rs` cover owned MIQP option/domain handling and full mixed-cone dimensions/indices. These are accounting and source-order guarantees, not measured resident-memory bounds.

The sparse backend really is sparse internally. Its conservative dense-fill upper estimate can reject models that might fit with a tighter symbolic estimate. This is a remaining scale limitation, not evidence that unrestricted large sparse benchmark requirements have passed.

## Algorithm references and dependency audit

The independent QP implementation follows the published proximal ADMM equations and primal/dual residuals in [OSQP's algorithm documentation](https://osqp.org/docs/solver/index.html); it is not an OSQP binding. Convexity proof is conservative: symmetric diagonal dominance with nonnegative diagonal, or checked positive LDL with a reconstruction/inverse-residual eigenvalue bound. Unsupported semidefinite matrices are Unknown/unproven rather than sampled and declared convex.

Clarabel is pinned to `=0.11.1`, Apache-2.0, upstream MSRV 1.70. `default-features=false, features=["serde"]` is necessary because this release references `serde_json::Error` unconditionally even when its serde feature is disabled. The enabled feature adds serde/serde_json/serde-big-array only; no native dense algebra, SDP, faer, external executable, proprietary engine, Python or Julia feature is enabled. Upstream owns unsafe FFI callback scaffolding, although this adapter uses only safe Rust callbacks; no claim of a transitively unsafe-free dependency graph is made.

Primary source: [Clarabel Rust guide](https://clarabel.org/stable/rust/getting_started_rs/) and [termination callback example](https://clarabel.org/stable/examples/rs/example_callback/). The backend's `Solved` or `AlmostSolved` status is not blindly promoted to Solvercraft Optimal.

## Remaining hard gaps

LP vertex bases are limited to 64 variables/512 normalized rows and a bounded basis-combination search; they are not reusable opaque sparse-factor/tableau states. Nonvertex optima or excessively degenerate/ill-conditioned active sets may return no basis/sensitivity report. QP primal/dual warm starts are not conic backend warm starts. Full large sparse benchmark scale, all convex PSD recognition, unbounded-ray reconstruction on unrestricted free conic models, complete presolve/cuts/advanced MIP controls, and numerical certification across every supported magnitude are not established. MIQP/MISOCP and SOS/indicators are bounded implementations with explicit restrictions, not full commercial-suite parity. SDK/facade/CLI/GUI integration and independent cross-backend verification remain separate requirements owned by their respective modules.

Independent review added `tests/certificate_review.rs`, covering min/max conic bounds, exhaustive binary optima/interrupted global bounds, method validation with a warm basis, validator allocation budgets, forged/perturbed bases, tiny finite blockers, the large-M feasible boundary, and product-rounding precision. Confirmed method/resource/Big-M defects were corrected before acceptance; product-rounding correctness is guarded explicitly rather than hidden by a small gap.

The arithmetic follow-up preserves the compiler's 16-byte `CompensatedSum` layout and adds separate fixed exact-product scratch. Its 1,619 independent Python Fraction fixtures match every output bit in both orders; 20,470 finite-exponent identity cases and million-term carry stress also execute. Duplicate coefficient sums that cannot be represented exactly (including 0.1+0.2) are explicitly refused. See [model arithmetic contract](../../crates/model/README.md). A CVaR regression exposed phase-I reduced-cost rounding after feasibility was already achieved; phase I now terminates from the known zero artificial-variable objective, while phase II still preserves genuinely small reduced costs.
